# Fix: linked subprojects can't save Claude memories

## Context

`scripts/°base/init/link-subproject-claude.sh` (aka `link_subproject.sh`) lets a subfolder of a monorepo share the root's `.claude/`, `.codex/`, settings, etc. via directory symlinks (`link_shared ".claude"` etc., lines 220-221), so launching Claude Code from inside that subfolder picks up the shared hooks/permissions.

Reproduced live in a scratch clone + linked subfolder: a session launched with cwd inside the linked subfolder correctly reports that subfolder as its own `cwd`/`transcript_path`, but Claude Code's **native auto-memory feature** still writes memory files into the **parent repo's** project bucket under `~/.claude/projects/<encoded-parent-path>/memory/` — never into the subfolder's own bucket. Confirmed via the `record-memory` hook's own debug dump (`ai/.debug` → `ai/output/debug/*-record-memory.json`): the `Write` tool call's `file_path` pointed at `.../base-test-clone/memory/MEMORY.md`, missing the `-my-subproject` suffix that the same payload's own `transcript_path` correctly had.

Meanwhile this repo's own `record-memory` hook computes its *source* directory from the literal subfolder path (`_encoded_project_dir()` in `scripts/°base/ai/hooks/_lib.py:363-369`, fed by `_subproject_root()` at `_lib.py:372-377`, which reads `CLAUDE_PROJECT_DIR` — correctly the subfolder, per the hook's own debug payload). Because Claude's native writer and this repo's hook disagree on which encoded directory is "the project", the memory file lands somewhere the hook never looks, and is silently never mirrored into `<subfolder>/ai/memory/` or committed at all.

Restructuring `.claude` away from a whole-directory symlink was considered and rejected by the user ("not symlinking kinda sucks") — instead, fix this by pinning Claude's own project-identity resolution via the documented `CLAUDE_CODE_PROJECT_DIR_NAME` environment variable, and teaching this repo's hooks to agree with it.

**Verified against the installed Claude Code binary** (`/home/user/.local/share/claude/versions/2.1.281`, disassembled strings, not docs alone): `CLAUDE_CODE_PROJECT_DIR_NAME` is a real, current env var that overrides the encoded project-directory name Claude uses under `<config-dir>/projects/`, gated on `CLAUDE_CONFIG_DIR` also being set in the environment, and validated against `^[A-Za-z0-9_-]{1,64}$` (no path separators, 1-64 chars, not a reserved device name). Setting only `CLAUDE_CODE_PROJECT_DIR_NAME` without `CLAUDE_CONFIG_DIR` is silently ignored.

## Approach

### 1. Generate a per-subfolder env file at link time

Add a new function to `scripts/°base/init/link-subproject-claude.sh` (alongside the existing `link_shared`/`copy_if_missing` helpers, called from the bottom list at lines 220-230), e.g. `seed_claude_project_env()`, that idempotently writes `<sub_dir>/.claude-project.env`:

```bash
# Generated by link_subproject.sh — source before launching Claude Code here.
export CLAUDE_CONFIG_DIR="${CLAUDE_CONFIG_DIR:-$HOME/.claude}"
export CLAUDE_CODE_PROJECT_DIR_NAME="<slug>"
```

`<slug>` = git-root-basename + sanitized relative path from git root (non `[A-Za-z0-9_-]` chars → `-`, collapse/trim dashes), truncated to fit 64 chars with an 8-hex-char sha1 suffix of the absolute path appended when truncation was needed (collision safety). Follow the existing `copy_if_missing` pattern (`link-subproject-claude.sh:122-144`) for idempotency: never overwrite an existing file, `git add` it since it's fully deterministic and safe to commit (the `CLAUDE_CONFIG_DIR` line is a passthrough default, not a hardcoded machine path).

Update the script's header comment and the seeded `CLAUDE.md` template (`scripts/°base/init/templates/CLAUDE.md`) to note: **source `.claude-project.env` before launching a Claude Code session from this subfolder** (`source .claude-project.env && claude-work` or whichever alias), otherwise memory/session storage will silently attach to the parent project.

### 2. Make this repo's own hooks agree with the override

`_encoded_project_dir()` in `scripts/°base/ai/hooks/_lib.py:363-369` currently always derives the encoded directory from the sanitized absolute path. Update it to mirror Claude's own gating logic: if both `CLAUDE_CONFIG_DIR` and `CLAUDE_CODE_PROJECT_DIR_NAME` are set and the latter matches `^[A-Za-z0-9_-]{1,64}$`, use it directly as the directory name; otherwise fall back to today's path-sanitizing behavior. This is the single shared helper — `scripts/°base/ai/memory/delete.py:12-16` already imports it from `_lib.py` rather than duplicating it (the `project_dual_codex_config_dirs` memory claiming it still hardcodes `~/.claude` is stale and should be corrected), so fixing it once fixes both the `record-memory` hook and the memory-delete CLI.

### 3. Tests

Extend `scripts/°base/tests/test_ai_hooks_base_routing.py` (or add a focused test near `test_memory_delete.py`, both of which already fake `CLAUDE_PROJECT_DIR` per the Explore findings) with a case that sets `CLAUDE_CONFIG_DIR` + `CLAUDE_CODE_PROJECT_DIR_NAME` and asserts `_encoded_project_dir()` returns `<config-dir>/projects/<slug>/` instead of the path-sanitized directory.
