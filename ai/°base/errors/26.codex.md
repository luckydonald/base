# UI — Codex

## Options for `/plan`:
```text
 Implement this plan?

› 1. Yes, implement this plan          Switch to Default and start coding.
  2. Yes, clear context and implement  Fresh thread. Context: 37% used.
  3. No, stay in Plan mode             Continue planning with the model.

  Press enter to confirm or esc to go back
```

The menu has no free-text acceptance note or denial-reason path. “No, stay in Plan mode” returns to the
ordinary prompt box; its observed hook sequence was `Stop`, then an ordinary `UserPromptSubmit`, with no
`exit_plan_mode` / `ExitPlanMode` event. The two acceptance paths still need independent payload captures.

“Yes, clear context and implement” is the Codex-specific modifier to preserve if and only if a matching
acceptance event exposes an explicit, stable context-clear field. Starting a fresh session alone is not enough
evidence to infer that tag.

## Options for commands
```text
Would you like to run the following command?

  Environment: local

  Reason: May I read the first line of /etc/os-release to capture the Codex permission menu? This is read-only and makes no repository changes.

  $ sed -n '1p' /etc/os-release

› 1. Yes, proceed (y)
  2. Yes, and don't ask again for commands that start with `sed -n 1p /etc/os-release` (p)
  3. No, and tell Codex what to do differently (esc)

  Press enter to confirm or esc to cancel
```

This menu has no inline text field. The third option is labelled “No, and tell Codex what to do differently”,
but its resulting follow-up path is still untested; do not assume it carries a reason until its event stream is
captured.

#### No, and tell Codex what to do differently
```text
■ Conversation interrupted - tell the model what to do differently. Something went wrong? Hit `/feedback` to report the issue.
```
